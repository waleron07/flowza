# План разработки web frontend (TDD)

## 1. Цель web части

`apps/web` — это клиентская часть Flowza для конечного пользователя.

Web frontend должен решать следующие задачи:

- регистрация клиента;
- login клиента;
- просмотр меню;
- работа с корзиной;
- оформление заказа;
- просмотр своих заказов;
- в дальнейшем: профиль клиента, история заказов, дополнительные сценарии лояльности.

Разработка ведется по **TDD-подходу**:

1. сначала описывается поведение экрана и пользовательский сценарий;
2. затем пишется тест;
3. затем реализуется минимальный рабочий код;
4. после прохождения тестов выполняется рефакторинг.

## 2. Зависимость от backend

Web frontend будет строиться поверх backend API.

На текущий момент с backend уже есть основа auth-слоя:

- `POST /auth/register`
- `POST /auth/login`
- `GET /auth/me`
- `DELETE /auth/me`

Это позволяет начинать клиентскую часть с auth и профиля пользователя, а затем двигаться к меню и заказам.

## 3. Техническая база web

Текущий стек `apps/web`:

- `React + TypeScript`
- `Vite`
- `MUI`
- `React Router`
- `Vitest`
- `Testing Library`

По мере разработки web части рекомендуется добавить:

- `React Query`
- `Axios`
- `Formik`
- `Yup`

## 4. UI и стилизация

### Дизайн-система

Для web frontend также используется библиотека `MUI`.

Это означает:

- все базовые UI-компоненты строятся на `@mui/material`;
- формы, кнопки, карточки, контейнеры и диалоги опираются на `MUI`;
- кастомизация внешнего вида идет через единый `theme`.

### Подход к стилям

Стилизация в `apps/web` также должна строиться через `theme` и `sx`.

Основные правила:

- прикладной UI не должен опираться на разрозненные `.css` файлы;
- стили конкретного компонента выносятся в `styles.ts`;
- компонент использует `sx`-объекты из `styles.ts`;
- цвета, отступы, размеры и типографика контролируются через theme-подход.

### Рекомендуемый паттерн компонентов

```text
ComponentName/
  index.tsx
  styles.ts
```

Где:

- `index.tsx` содержит логику, разметку и привязку событий;
- `styles.ts` содержит объект `sx` для `MUI`.

Именно этот стиль реализации считается целевым и для `apps/web`.

## 5. Основные принципы web frontend

- бизнес-логика остается на backend;
- web frontend отвечает за UX и взаимодействие пользователя;
- каждая фича должна иметь:
  - `loading`
  - `error`
  - `empty-state`
- тесты описываются на кириллице;
- интерфейс строится модульно;
- структура должна быть готова к масштабированию и мобильному приложению в будущем.

## 7. MVP web

### Что должно быть в MVP

- регистрация клиента;
- login клиента;
- protected routes для авторизованного клиента;
- базовый профиль;
- удаление собственного аккаунта;
- меню;
- корзина;
- оформление заказа;
- история своих заказов.

### Что пока не входит в первый web MVP

- сложная персонализация;
- избранное;
- отзывы;
- бонусы и промокоды;
- push/email уведомления;
- сложный профиль с настройками.

## 8. Этапы разработки web

### Этап 0. Каркас web и тестовой среды

**Оценка:** 1-2 дня

#### Что сделать

- подтвердить структуру `apps/web`;
- подключить `MUI ThemeProvider`;
- настроить `Vitest`;
- настроить `Testing Library`;
- подготовить providers;
- подготовить router;
- подготовить базовую структуру страниц.

#### Что уже выполнено

- поднят каркас `React + TypeScript`;
- проходит `build`;
- проходит `lint`.

#### Результат этапа

Web frontend готов к разработке пользовательских сценариев.

---

### Этап 1. Auth клиента

**Оценка:** 2-4 дня

#### Сначала описать тестами

- успешная регистрация клиента;
- ошибка регистрации без валидных данных;
- успешный login;
- ошибка login при неверных данных;
- сохранение токена;
- protected route без токена недоступен;
- logout очищает сессию;
- удаление собственного аккаунта завершает сессию.

#### После тестов реализовать

- страницу регистрации;
- страницу login;
- auth/session слой;
- protected routes;
- интеграцию с:
  - `POST /auth/register`
  - `POST /auth/login`
  - `GET /auth/me`
  - `DELETE /auth/me`

#### Результат этапа

Клиент может зарегистрироваться, войти и управлять своей сессией.

---

### Этап 2. Профиль клиента

**Оценка:** 1 день

#### Сначала описать тестами

- профиль отображает данные клиента;
- профиль не открывается без токена;
- удаление аккаунта вызывает `DELETE /auth/me`;
- после удаления пользователь вылогинивается.

#### После тестов реализовать

- страницу профиля;
- отображение `firstName`, `phone`, `role`;
- кнопку удаления аккаунта;
- подтверждение удаления.

#### Результат этапа

Есть базовый профиль клиента.

---

### Этап 3. Меню

**Оценка:** 3-5 дней

#### Сначала описать тестами

- список категорий отображается;
- список продуктов отображается;
- корректно работают `loading/error/empty-state`;
- карточка продукта рендерится корректно.

#### После тестов реализовать

- страницу меню;
- список категорий;
- карточки продуктов;
- фильтрацию по категориям.

#### Результат этапа

Клиент может просматривать меню.

---

### Этап 4. Корзина

**Оценка:** 2-3 дня

#### Сначала описать тестами

- добавление товара в корзину;
- изменение количества;
- удаление позиции;
- пересчет итоговой суммы;
- корректное пустое состояние корзины.

#### После тестов реализовать

- cart store;
- страницу корзины;
- компоненты позиций корзины;
- итоговый блок заказа.

#### Результат этапа

Клиент может собрать заказ.

---

### Этап 5. Оформление заказа

**Оценка:** 2-3 дня

#### Сначала описать тестами

- отправка валидного заказа;
- запрет отправки пустой корзины;
- успешный сценарий оформления;
- ошибка оформления.

#### После тестов реализовать

- checkout экран;
- интеграцию с backend заказов;
- очистку корзины после успешной отправки.

#### Результат этапа

Клиент может оформить заказ.

---

### Этап 6. История заказов

**Оценка:** 1-2 дня

#### Сначала описать тестами

- список заказов отображается;
- статусы отображаются корректно;
- пустое состояние работает;
- ошибки загрузки отображаются.

#### После тестов реализовать

- страницу истории заказов;
- список заказов клиента;
- отображение статуса заказа.

#### Результат этапа

Клиент видит свои заказы после оформления.

## 10. Минимальный набор тестов для web MVP

### Auth

- успешная регистрация;
- ошибка регистрации;
- успешный login;
- ошибка login;
- protected route без токена;
- logout.

### Profile

- загрузка профиля;
- удаление аккаунта;
- очистка сессии после удаления.

### Menu / Cart / Checkout

- отображение меню;
- добавление товара в корзину;
- изменение количества;
- отправка заказа;
- успешный checkout;
- ошибка checkout.

## 11. Итог

`apps/web` нужно развивать как отдельный клиентский интерфейс для пользователя, но по тем же инженерным правилам, что и `apps/admin`:

- `MUI` как UI-основа;
- стили через `theme` и `sx`;
- TDD;
- модульная структура;
- backend-first контракты.

Это позволит держать единый стиль разработки между `admin` и `web`, но не смешивать сценарии сотрудников и клиентов.
